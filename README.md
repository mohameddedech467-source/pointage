# نظام حضور الموظفين عبر QR (Expo + Supabase)

تطبيق React Native (Expo) بسيط لتسجيل حضور وانصراف الموظفين عن طريق مسح رمز QR
مطبوع على بطاقة الدخول، مع لوحة تحكم للمسؤول.

## الميزات

- **شاشة رئيسية** بزرّين: "المسؤول" و "البواب".
- **دخول المسؤول** برمز سرّي: `Admin@2023`.
- **إدارة الموظفين**: إضافة موظف جديد وتوليد بطاقة QR خاصة به تلقائياً.
- **بطاقة الموظف**: عرض رمز QR قابل للحفظ في الصور أو المشاركة/الطباعة.
- **ماسح QR سريع ودقيق للبواب**:
  - يفتح الكاميرا ويطلب الإذن تلقائياً فور الدخول للشاشة.
  - اهتزاز (Haptics) فوري يفرّق بين نجاح العملية وخطئها دون الحاجة للنظر للشاشة.
  - يمنع تسجيل نفس البطاقة مرتين خلال ثوانٍ قليلة بالخطأ (حماية من التكرار).
  - يستأنف المسح تلقائياً بعد كل عملية، مع زر "مسح فوري" للاستئناف اليدوي.
  - عدّاد لعدد عمليات المسح خلال الجلسة، وزر لتشغيل الفلاش.
- **تقارير احترافية للمسؤول**:
  - تبويب **نظرة عامة**: بطاقات إحصائية (موظفون نشطون، إجمالي الساعات، المتوسط، عدد الجلسات) وترتيب الموظفين حسب الساعات لفترات اليوم/الأسبوع/الشهر.
  - تبويب **التقويم**: تقويم شهري تفاعلي يُظهر نقطة على كل يوم فيه حضور، وعند اختيار يوم تظهر تفاصيل كل موظف (وقت الدخول، وقت الخروج، إجمالي الساعات، وحالة "قيد العمل الآن" إن لم يسجّل خروجاً بعد).
- تصميم عصري واحترافي بأيقونات موحّدة، بطاقات مستديرة وظلال ناعمة، وواجهة عربية RTL نظيفة.
- جاهز للتطوير والتحويل لتطبيق حقيقي (APK / IPA أو نشر عبر EAS).

## خطوات التشغيل

### 1) إنشاء مشروع Supabase
1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** والصق محتوى الملف `supabase/schema.sql` ثم شغّله.
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`

### 2) إعداد المشروع محلياً
```bash
# فك ضغط المشروع ثم:
cd attendance-app
npm install

# أنشئ ملف .env من المثال وضع بياناتك
cp .env.example .env
```
عدّل `.env`:
```
EXPO_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxxxxxxxxxx
```

### 3) التشغيل
```bash
npx expo start
```
امسح رمز QR بتطبيق **Expo Go** على هاتفك (Android/iOS)، أو شغّله على المحاكي.

> ملاحظة: لتجربة ماسح QR (شاشة البواب) يجب التشغيل على جهاز حقيقي أو محاكي يدعم الكاميرا،
> وقبول إذن الكاميرا عند الطلب.

## كيف يعمل نظام الحضور؟

- كل موظف له `id` فريد في جدول `employees`.
- عند توليد البطاقة، يُخزَّن داخل QR نص JSON مثل:
  `{"type":"employee","id":"<employee-uuid>"}`
- عند مسح البواب للرمز:
  1. يبحث عن الموظف بواسطة `id`.
  2. يتحقق من آخر حركة له في `attendance_records`.
  3. إذا كانت آخر حركة "دخول" يسجّل "خروج"، والعكس صحيح، ويحسب ذلك تلقائياً.
- التقارير تحسب مجموع الساعات بمطابقة كل "دخول" مع "خروج" يليه زمنياً.

## استكشاف الأخطاء الشائعة

- **رسالة "Project is incompatible with this version of Expo Go" أو اختلاف SDK**:
  تطبيق Expo Go المثبت على هاتفك يدعم إصدار SDK معيّن فقط (يظهر في الرسالة، مثل SDK 54).
  هذا المشروع مضبوط على نفس الإصدار، لكن إذا تغيّر إصدار Expo Go لديك مستقبلاً، صحّح التبعيات تلقائياً بالأمر:
  ```bash
  npx expo install --fix
  ```
  هذا الأمر يقرأ إصدار Expo المثبت في `package.json` ويضبط كل الحزم (`react`, `react-native`,
  `expo-camera`, ...) على النسخ المتوافقة تلقائياً — نفّذه دائماً بعد `npm install` الأولى
  أو بعد أي تغيير في إصدار Expo.

- **رسالة "Unable to resolve asset ./assets/icon.png"**:
  المشروع يتضمن أيقونات بسيطة جاهزة في مجلد `assets/` (icon.png, adaptive-icon.png, splash.png).
  يمكنك استبدالها بأيقونة تصميمك الخاصة بنفس الأسماء ونفس المسار دون تعديل `app.json`.

- **رسالة "Cannot find module 'babel-preset-expo'"**:
  هذه الحزمة (`babel-preset-expo`) مطلوبة لتشغيل Babel مع Expo وهي مضافة الآن في
  `devDependencies` بالمشروع. إن ظهر هذا الخطأ، احذف `node_modules` و `package-lock.json`
  وأعد التثبيت من جديد:
  ```bash
  rmdir /s /q node_modules   # على ويندوز
  del package-lock.json
  npm install
  ```

## تحويل التطبيق إلى APK / نشره

المشروع جاهز للبناء عبر **EAS Build** التابع لـ Expo:

```bash
npm install -g eas-cli
eas login
eas build:configure
eas build --platform android   # لإنشاء APK/AAB
eas build --platform ios       # لإنشاء بناء iOS (يتطلب حساب Apple Developer)
```

بعد الانتهاء ستحصل على رابط لتحميل ملف APK (أندرويد) يمكن تثبيته مباشرة على الأجهزة،
أو رفعه على Google Play / App Store.

## ملاحظات أمنية مهمة (للتطوير المستقبلي)

- رمز دخول المسؤول `Admin@2023` مضمّن حالياً داخل التطبيق للتبسيط. لمشروع حقيقي يُفضّل:
  - استخدام **Supabase Auth** لتسجيل دخول حقيقي للمسؤولين.
  - أو التحقق من الرمز عبر **Edge Function** بدل تخزينه في كود العميل.
- سياسات RLS الحالية في `schema.sql` مفتوحة (لتسهيل التجربة). في الإنتاج، قيّدها بحيث:
  - القراءة/الكتابة على `employees` و `attendance_records` تتطلب مصادقة المسؤول أو البواب.
- يمكن إضافة توقيع (HMAC) داخل محتوى QR لمنع تزوير البطاقات يدوياً.
